# Hopingo — le calcul en jouant

A Duolingo-style practice app for mental arithmetic and times tables, fractions, signed numbers, powers and square roots (HarmoS 5H–11H and gymnase, in French or English), now growing towards the first two years of EPFL (BA1–BA4, see `docs/plan-universite.md` and the implementation spec `docs/universite/README.md`). It is fully static, with no server: everything runs in the browser and progress is saved in `localStorage`.

## Run it

ES modules don't load from `file://`, so serve the folder:

```sh
npm run serve        # python -m http.server 8080, then open http://localhost:8080
npm test             # math core, symbolic core, judges, content generators, learner engine
npm run samples      # writes docs/samples-<unit>.md for content review
npm run smoke        # drives the app in headless Edge (dev tool, not in npm test): see tools/browser-smoke.js
```

There are no dependencies and no build step.

**Language.** Réglages → Langue (also on the first screen of a device) switches between French and English. It is a setting of the device (`localStorage` key `hopingo.lang`), not of a profile, and the page reloads. The app is written in French: every text shown goes through `t()` (`js/i18n.js`), which looks the French text up in `js/i18n/en/*.js` and falls back to the French when an entry is missing. Skill titles, descriptions and intro cards are translated in place when the catalogue loads (`localize`). `node tools/i18n-strings.js --check` counts the catalogue texts translated per unit; in the browser, `hopingoMissing()` lists the texts shown so far that have no translation. `HOPINGO_LANG=en` runs Node tools in English. Answers keep the French input language that the parsers and checkers read (decimal comma, « x = 2 ou x = 3 »); in English only what is shown changes: numbers are drawn with a decimal point, the keys « ou », « et » show « or », « and » (`showNumbers` in `js/i18n.js` for the page, `decimalComma` in `js/ui/keypad.js` for the answer field).

**Saving.** Progress lives in `localStorage`. Réglages → « Télécharger la sauvegarde » downloads a small JSON file (`hopingo-<name>-<date>.json`); « Charger un fichier » (or « Charger une sauvegarde » on the first screen of a new device) loads it. Old `HOPINGO1-…` codes saved in a .txt file still load. See `exportFile` and `importSave` in `js/store.js`.

**Test mode.** A profile named `nathmo` with the bee avatar (🐝) can open every skill on the map, to try any part of the tree. Everything else works as usual: answers are judged, mastery and traps are recorded, and the map still shows in grey (🔓) the skills the normal path would not have unlocked yet. See `isTester` and `canOpen` in `js/engine/learner.js`.

## Deploy on GitHub Pages

Push the folder to a repository, then go to **Settings → Pages → Deploy from a branch** and pick `main` / root. `.nojekyll` makes Pages serve the files as they are.

## How it works

|---|---|---|
| Exact math | `js/math/rational.js`, `expr.js` | Exact rationals. Parses keypad text, where `/` is the fraction bar, `^` an exponent and `√` a root. √2 × √8 and (√7)² are evaluated exactly. |
| Solver | `js/math/solver.js` | Canonical step-by-step solutions (signs, powers, roots included), used for guided blanks, hints and worked examples. |
| Mistakes | `js/math/malrules.js`, `diagnose.js` | Known errors (« pièges ») as rules. A wrong line is replayed under each rule, and under misreadings of its structure (priorities, brackets, −3² vs (−3)², √(a+b) = √a + √b…), to name the mistake. |
| Judge | `js/math/judge.js` | A line is valid if it keeps the exact value of the previous one, so any method is accepted. |
| Math input | `js/ui/keypad.js`, `js/ui/keys-needed.js` | The answer field keeps a line of characters and a caret, but draws it in 2D as it is typed, the way the parsers read it: fractions of any factor (12/x, 1/(x + 1), (x + 1)/2; 1/2x is ½·x), exponents (x^(n + 1), e^(2x)), radicals over their argument (√(x + 1), √2), \|…\|. Brackets around a numerator, a denominator, an exponent or a radicand are not drawn, as in the question; the caret skips the positions next to them. The fraction key with nothing before the caret gives an empty fraction, the caret in the numerator; pressed again it goes to the denominator. Every keypad for letters has the fraction, the power, √ and both brackets. `keysForItem(item)` gives an item its tabs: its own keypads, the small keypads its lines need (`keysFor`), and a tab « + … » with whatever else the question shows or the answer, the start line and the reference lines use (fraction, power, √, π, e, functions, \|·\|, letters, relations, « ; »). |
| Free steps | `js/judges/steps.js`, `js/ui/draft.js` | Above every typed answer, « + Ajouter une étape » keeps the line being typed, drawn in 2D, and the student goes on from it (« Recopier la ligne », Maj + Entrée). When the item has a `start` (`{math}`: the equation or expression of the question), each line is checked against the previous one: same solution set for an equation (judge `solset` on the domain of the start, parameters sampled; « ; » reads « ou »), same value for an expression (`equiv`) or a number (`js/math/judge.js`), the solution of a system satisfies it, a formula still holds with the answer. A wrong line is flagged and stays in the field to correct, with its trap named (the classic moves of `equations.js`, a term not multiplied when clearing a denominator, the item's own traps). Without a start the lines are « brouillon »: kept, not checked. The answer (the field, or the last line) is still judged by the item's checker. |

The checker says what is left to do and names the trap. |

**The map is a tree by school year** (`js/ui/screens/home.js`). One band per year (5H … 11H, gymnase, CMS, BA1 … BA4); in a band, one column per unit with its skills of that year. Columns that do not need each other stand side by side, and a column that needs another column of the same band goes on the line below. Inside a column, skills are in rows by prerequisite depth, so skills that do not need each other stand side by side too. The rail of years on the right scrolls the map fast (tap a year or drag along the rail) and follows the scrolling. The head of a column opens the unit: progress over all its years, pin the branch, « Je connais déjà ce module », its mock exams.

**The path branches.** After the first mental arithmetic, several units are open at once. « Continuer » keeps up to 3 active branches and moves from one to the next at each lesson, so topics mix; a new branch starts with the skill that opens the most others, at the student's current level. A branch can be pinned on the map, any open skill can be started, and a closed skill shows the prerequisite it waits for. Prerequisites are only the skills the exercises really use.

**Adapting to the student:**
- **Difficulty:** each skill has a level from 1 to 5. Two fast correct answers move it up a level. Two mistakes, or three slow answers, move it down. "Slow" is measured against the student's own pace on that skill.
- **Regression:** failing again at level 1 sends practice to the weakest prerequisite, marked 🧱/🩹 on the map, until that skill is solid.
- **Spaced review:** mastered skills come back for review, and the interval ×2.5 after each success. Skills skipped by the placement skim are due right away, so the reviews confirm them.
- **Spoiled chapters:** a mistake made in a later skill and named by a trap that belongs to an earlier, mastered skill (a fraction trap while doing algebra) is evidence against that earlier skill: its estimate drops and it is due for review at once; after two or three such mistakes it is no longer mastered (🔁 on the map) and « Continuer » redoes it first. When a student keeps failing at level 1, the repair goes to the chapter the trap names, else to the weakest prerequisite.
- **Implicit review:** a right answer without hints at level 3 or more uses the skill's prerequisites: a mastered prerequisite that is due counts as reviewed (once a day, interval ×1.5).
- **Solid (💎):** a skill whose review interval reached 60 days (about four reviews passed in a row: 2, 5, 12, 30, 75 days) is anchored in long-term memory. It still comes back, at most every 120 days, and its sheet on the map says when.
- **Traps:** a mistake becomes a trap after it happens twice. It is beaten by answering the questions that bait it correctly on 3 different days.

**Fast series** (times tables, sums to 20, squares, mental ± ):
- 15 short questions, no "Vérifier": the answer is judged as soon as it has enough digits, and a right answer moves straight on.
- The response time is measured but never shown. A fact counts as automatic when it is right in about 3 seconds.
- Each fact has its own spaced memory. A series mixes about 70 % known facts with a few new or fragile ones, and a missed fact comes back two questions later.
- A mistake shows the full fact, the trap with the question's own numbers, and a strategy (9 × 6 = 60 − 6).

**Step-by-step modes** (multi-step skills and the operation skills of every unit):
- **Guided:** fill in the new numbers of each canonical step. A new negative number is one blank, sign included.
- **Tap then solve:** tap the operation to do next (an operator, an exponent or a root sign). Tapping the wrong one is caught as a priority mistake.
- **Free lines:** rewrite the expression line by line, with "Recopier la ligne" and hints.

**Steps before an answer:** every typed answer (school and university) can be prepared in as many lines as needed, written on screen above the field. Lines are checked when the item knows its start, else kept as brouillon (see « Free steps » above).

To add a skill:
1. Add it to its unit's list in `js/content/skills.js` (a university skill: `js/content/uni/<unit>.skills.js`), with its year, prerequisites and intro.
2. Add a generator to `GEN` in the unit's file in `js/content/` (university: `js/content/uni/<unit>.js`; a new unit is listed in `js/content/uni/index.js` and `uni/generators.js`). An `answer` item that transforms an equation or an expression gives it as `start: {math}` (keypad text), so that the student's steps are checked.
3. Add any new mistakes to `RULES` in `js/math/malrules.js` (university: `js/cas/rules/<module>.js`, with a `transform` that replays the mistake on the previous line), with a general explanation for when no numbers are available.
4. Run `npm test`. It generates 200 items per skill and checks they are consistent, and checks every trap points to a real skill. For university skills it also replays every reference solution through its own judge, and checks each trap names its own example.
